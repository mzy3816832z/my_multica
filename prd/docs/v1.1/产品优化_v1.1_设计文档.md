# 上海公寓租赁平台 产品优化 V1.1 系统设计文档

## 1. 概述

### 1.1 需求背景

V1.0 已跑通「商家发布 → 平台审核 → 租客浏览/收藏 → 站内信通知」闭环，但实测与竞品对标暴露三类问题：
- 找房效率低：无排序、无地图、无地铁维度，搜索仅支持名称
- 信息不完整/信任感弱：无面积/朝向/费用明细、PC端体验差
- 基础体验硬伤：Token 30分钟强制登出、站内信不跳转、字典硬编码

### 1.2 设计目标

基于《产品优化PRD V1.1》定义的功能清单（F1-F18），对现有系统进行增量式优化，聚焦：
- 租客侧找房效率提升（排序/搜索/地图/地铁筛选）
- 房源信息完整度提升（面积/朝向/费用字段扩展）
- 体验硬伤修复（PC响应式/Token续期/消息跳转/存量缺陷）

### 1.3 版本说明

本次为 V1.0 → V1.1 迭代版本，在现有 Django DRF + Vue3 技术栈基础上增量开发。
- 向后兼容：新增字段全部可空，存量房源不强制补录
- 不破坏 V1.0 闭环：发布/审核/收藏/消息主流程不变
- PRD 文档：`prd/docs/iterations/v1.1/产品优化PRD-V1.1.md`
- 关联 Issue：YUZ-195

## 3. 详细设计

### 3.1 M1 房源字段扩展

**功能描述**：新增面积、朝向、可入住时间、费用明细、经纬度字段，扩展数据模型与API。

**技术方案**：
- 数据库变更：对 RoomType 表新增 area/orientation/available_date；对 Apartment 表新增 longitude/latitude/property_fee/water_fee/electric_fee/service_fee/other_fees/min_area/verified
- Django Migration 新增字段全部 nullable，存量数据兼容
- Apartment.min_area 缓存字段：参照 min_monthly_rent 模式，当 room_types 变更时通过信号/save 钩子重新计算该公寓下所有房型面积的最小值
- Serializer 同步更新 apartments/ 和 merchant/ 下的序列化器
- 朝向复用已有系统字典 `orientation`（V1.0 已建未用）

**数据模型变更**：

RoomType 新增字段：
| 字段 | 类型 | 必填 | 校验 | 默认 |
|------|------|------|------|------|
| area | DecimalField(max_digits=6, decimal_places=1) | 否(null=True) | 0.5-500 | null |
| orientation | CharField(max_length=30) | 否(null=True) | 朝向字典code | null |
| available_date | DateField | 否(null=True) | ≥当前日期 | null(随时入住) |

Apartment 新增字段：
| 字段 | 类型 | 必填 | 校验 | 默认 |
|------|------|------|------|------|
| longitude | DecimalField(max_digits=9, decimal_places=6) | 否(null=True) | -180~180 | null |
| latitude | DecimalField(max_digits=9, decimal_places=6) | 否(null=True) | -90~90 | null |
| property_fee | IntegerField | 否(null=True) | ≥0 | null |
| water_fee | CharField(max_length=30) | 否(null=True) | 字典code | null |
| electric_fee | CharField(max_length=30) | 否(null=True) | 字典code | null |
| service_fee | IntegerField | 否(null=True) | ≥0 | null |
| other_fees | CharField(max_length=100) | 否(blank=True) | ≤100字 | "" |
| min_area | DecimalField(max_digits=6, decimal_places=1) | 否(null=True) | 缓存字段 | null |
| verified | BooleanField | 否 | - | False |

**费用字典**：新增 system_dict category `fee_type`（水费/电费），枚举值：`civilian`(民水民电)、`commercial`(商水商电)、`metered`(按表计费)。

**接口变更**：
- `POST/PUT /api/v1/merchant/apartments` — 请求体新增上述字段
- `GET /api/v1/apartments` — 列表返回新增 min_area
- `GET /api/v1/apartments/{id}` — 详情返回新增字段
- `GET /api/v1/merchant/apartments/{id}` — 编辑回显包含新增字段

### 3.2 M2 列表排序

**功能描述**：列表页新增排序下拉，支持最新/价格/面积排序，切换时重置分页。

**技术方案**：
- 后端：`GET /api/v1/apartments` 新增 query 参数 `sort`，枚举值：`latest`(默认)、`price_asc`、`price_desc`、`area_desc`、`area_asc`
  - price 排序按 min_monthly_rent，null 值排最后
  - area 排序按 min_area（依赖M1），null 值排最后
  - 后端 ORM 使用 `order_by(F('field').asc(nulls_last=True))` 或等效实现
- 前端：列表页 FilterBar 区域新增排序下拉组件（Vant DropdownMenu），切换选项时重置 page=1 并重新请求

**接口变更**：
- `GET /api/v1/apartments` 新增参数：`sort` (string, 可选, 默认 "latest")

### 3.3 M3 搜索扩展

**功能描述**：搜索范围从仅名称扩展到名称+地址+描述模糊匹配；新增搜索历史本地存储。

**技术方案**：
- 后端：`GET /api/v1/apartments` 的 `keyword` 参数匹配逻辑从仅 name 扩展为 name + detail_address + description，使用 Django `Q` 对象 OR 组合，权重按 name > detail_address > description 排序（使用 Case/When 或 raw SQL relevance）
- 前端：
  - 搜索弹窗 UI 重构：搜索输入框 + 历史记录列表 + 热门区域快捷词
  - 历史记录使用 localStorage 存储，key: `search_history`，value: `["keyword1", "keyword2", ...]`，最多10条，最新在前
  - 热门区域快捷词从 districts 接口取房源数 Top5 行政区名
- 空结果时展示空态 + "试试搜索行政区或街道名"提示 + 热门区域快捷词

**接口变更**：
- `GET /api/v1/apartments` — keyword 参数模糊匹配逻辑扩展（兼容旧行为）
- 新增 `GET /api/v1/apartments/hot-districts` — 返回房源数 Top5 行政区 `[{district_id, name, count}]`

### 3.6 M6 Token无感续期

**功能描述**：access token 过期时自动使用 refresh token 刷新，用户无感知。

**技术方案**：
- 修改 `web/src/api/` 下 Axios 实例的响应拦截器：
  - 遇到 401 时，检查是否已有正在进行中的 refresh 请求
  - 若无，发起 `POST /api/v1/auth/refresh` 获取新 access token
  - 若有，将当前请求加入等待队列，refresh 完成后统一重放
  - refresh 接口本身也返回 401 时，清除登录态并跳转登录页
- 后端：在现有 JWT 认证基础上，确保 `POST /api/v1/auth/refresh` 接口正常工作（refresh token 有效期内返回新 access token）

**接口**：
- 复用现有 `POST /api/v1/auth/refresh`（需确认接口存在；如不存在需新增）

### 3.7 M7 站内信跳转

**功能描述**：站内信列表点击消息后跳转至关联房源编辑页或审核详情页。

**技术方案**：
- 前端：
  - 消息列表 `MessageItem` 组件增加点击事件
  - 驳回类消息（first_rejected/change_rejected）：点击后先调 `POST /api/v1/messages/{id}/read` 标记已读，再根据消息类型跳转：
    - 首次驳回 → 商家房源编辑页 `/profile/apartments/{apartment_id}/edit`
    - 变更驳回 → 审核详情页（商家视图）
  - 房源已删除时（查询返回404）：toast "该房源已删除"，仅标记已读不跳转
- 消息列表项需展示关联房源名称，后端 `GET /api/v1/messages` 接口需 `select_related('related_apartment')` 并返回 `related_apartment_name`

**接口变更**：
- `GET /api/v1/messages` 返回新增字段：`related_apartment_name` (string)

**技术方案**：
- 数据准备：
  - 新增数据库表 `metro_lines`（线路名、编码）、`metro_stations`（站点名、所属线路、经纬度）
  - 种子数据脚本导入上海地铁线路站点数据
- 筛选逻辑：
  - 筛选抽屉新增"地铁"区域：线路下拉 → 站点多选
  - 后端筛选：给定站点ID列表 → 查询站点经纬度 → 计算与房源经纬度距离 → 返回 ≤ 1.5km 的房源
  - 使用 `ST_Distance` (PostGIS) 或 Haversine 公式计算；PostGIS 需先启用扩展
- 与行政区筛选关系：【待确认 AND/OR，先按 AND 实现】
- 无经纬度房源不在地铁筛选结果中出现

**接口变更**：
- 新增 `GET /api/v1/metro/lines` — 返回 `[{id, name, code, stations: [{id, name}]}]`
- `GET /api/v1/apartments` — 新增参数 `metro_station_ids` (array, 可选)

## 6. 非功能性设计

### 6.1 性能
- 列表/筛选接口 P95 ≤ 500ms：筛选字段建索引（min_monthly_rent、min_area、district_id）
- 图片懒加载 + WebP 格式
- 地图标记 > 200 个时强制聚合
- min_area/min_monthly_rent 缓存字段减少 JOIN

### 6.2 安全
- 新增字段接口参数校验，包含面积边界(0.5-500)、费用≥0
- verified 字段仅管理员可写，序列化器做角色校验
- 地理编码 Key 服务端代理，不下发前端
- 管理员密码改环境变量注入，移除硬编码

### 6.3 兼容性
- 迁移脚本所有新字段 nullable，保证向后兼容
- 前端无经纬度/无面积时降级隐藏对应模块
- 移动端 iOS Safari/Android Chrome 近两年版本；PC Chrome/Edge 近两年版本

### 6.4 可扩展性
- 费用字典使用 system_dict 统一管理，新增费用类型只需加字典数据
- 地图服务通过后端代理，切换地图服务商只需改后端代码
- 排序策略可扩展：sort 参数枚举可新增，后端用策略模式或映射表
