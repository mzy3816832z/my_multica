## 2. 需求背景与目标

### 2.1 背景

V1.0 已跑通「商家发布 → 平台审核 → 租客浏览/收藏 → 站内信通知」闭环，但实测与竞品对标暴露出三类问题：

1. **找房效率低**：仅支持按公寓名称搜索，无排序、无地图、无地铁维度，而贝壳/自如/Wellcee 均把"位置"作为第一筛选维度；租客找到目标房源的路径过长。
2. **信息不完整、信任感弱**：房源无面积、无朝向（数据模型有朝向字典但发布表单未收集）、无周边配套、无费用明细（物业费/水电/服务费），图片无真实性约束；详情页只有文字地址和电话。
3. **基础体验有硬伤**：PC 端被强制限制为 480px 居中（PRD 声称 PC 响应式但未实现）、无 token 续期导致用户 30 分钟被强制登出、站内信点击不跳转、字典前后端两处硬编码、测试报告存在 4 个失败用例。

### 2.2 目标

| 目标 | 衡量指标 |
|---|---|
| 提升找房效率 | 列表页增加排序与位置维度筛选；搜索支持地址/描述；筛选到详情点击路径 ≤ 3 步 |
| 提升房源信息完整度与信任度 | 房源关键字段（面积/朝向/费用）完整率 ≥ 90%；新增"平台核验"标识 |
| 修复体验硬伤 | PC 端可用；登录态无感续期；站内信可跳转；存量 4 个失败测试用例清零 |
| 不破坏 V1.0 闭环 | 发布/审核/收藏/消息主流程回归测试 100% 通过 |

### 2.3 本期范围

- **In Scope**：租客侧找房体验（搜索/筛选/排序/地图/详情）、房源信息字段扩展、商家发布表单同步扩展、PC 响应式、登录续期、消息跳转、存量缺陷修复。
- **Out of Scope**（V2.0+ 候选）：在线签约、在线支付、IM 聊天、VR 看房、预约看房、租后服务（保洁/维修）、双人通勤找房、AI 问答。这些在 §9 风险与依赖中登记，不在本期实现。

## 3. 功能清单与优先级矩阵

优先级定义：**P0** 本期必须上线（硬伤修复 + 找房核心链路）；**P1** 重要，本期资源允许即做，最晚 V1.2；**P2** 增强体验，可排入 backlog。

| # | 模块 | 功能点 | 优先级 | 来源 | 业务价值 |
|---|---|---|---|---|---|
| F1 | 列表筛选 | 列表排序（最新/价格升/价格降/面积升/面积降） | P0 | 贝壳/自如标配；当前无任何排序 | 找房核心路径，实现成本低 |
| F2 | 列表筛选 | 搜索范围扩展：名称+地址+描述；搜索历史（本地） | P0 | 实测痛点：仅名称搜索 | 提升搜索命中率 |
| F3 | 房源信息 | 字段扩展：面积(㎡)、朝向、入住时间、费用明细（物业费/水/电/服务费/网费） | P0 | 自如/冠寓标配；当前缺失 | 决策信息完整，减少线下沟通 |
| F4 | 房源信息 | 详情页费用明细与配套设施展示组件 | P0 | 随 F3 | 信息透明，建立信任 |
| F5 | 体验修复 | PC 端响应式布局（解除 480px 写死限制） | P0 | V1.0 PRD 承诺未兑现 | 商家/管理员主要在 PC 操作 |
| F6 | 体验修复 | Token 无感刷新（401 前自动 refresh） | P0 | 实测痛点：30 分钟强制登出 | 基础可用性 |
| F7 | 消息 | 站内信点击跳转关联房源/审核单 | P0 | V1.0 PRD §7.3 已定义未实现 | 闭环通知链路 |
| F8 | 质量 | 存量缺陷清零：手机号号段校验、详情页字典 label 翻译、收藏列表字段映射、清理硬编码与调试文件 | P0 | 测试报告 4 失败用例 | 质量底线 |
| F9 | 地图找房 | 房源打点地图页（列表↔地图双视图），基于行政区/街道聚合 | P1 | 贝壳/自如核心功能 | 位置是租房第一决策因子 |
| F10 | 房源信息 | 详情页位置模块：静态地图 + 周边配套（地铁/公交/商超，文字列表） | P1 | 贝壳"周边"模块 | 减少跳失 |
| F11 | 信任体系 | "平台核验"标识 + 图片实拍提示 + 商家实名信息展示 | P1 | 贝壳实地核验、自如统一装修背书 | 平台差异化信任资产 |
| F12 | 商家端 | 发布表单同步 F3 字段 + 图片压缩/排序优化 + 草稿保存 | P1 | 商家实测痛点 | 发布转化率 |
| F13 | 列表筛选 | 地铁线路筛选（线路→站点） | P1 | 贝壳/自如"地铁找房" | 上海租客强通勤导向 |
| F14 | 租客端 | 浏览历史（本地记录） | P2 | 贝壳/自如标配 | 回访便利 |
| F15 | 租客端 | 房源对比（最多 3 套，关键字段并排） | P2 | 汽车之家/贝壳借鉴 | 决策辅助 |
| F16 | 租客端 | 房源分享（生成分享卡片/链接） | P2 | 全平台标配 | 自传播获客 |
| F17 | 消息 | 审核通过也发站内信；新增系统通知类型 | P2 | V1.0 明确"通过不通知"，但商家有获知诉求【待确认】 | 商家体验 |
| F18 | 数据 | 收藏数/浏览量统计（仅商家可见自己房源数据） | P2 | 贝壳房东端 | 商家经营感知 |

> 明确**不做**（本期）：VR 看房、在线签约/支付、IM、预约看房、双人通勤找房、AI 助手。理由：要么超出"信息汇总平台"定位，要么依赖外部资源（VR 拍摄、支付牌照、IM SDK），投入产出比不适合本期。

## 4. 详细需求说明

### 4.1 F1 列表排序

**用户故事**：作为租客，我希望按价格/面积/最新排序房源列表，以便快速找到符合预算的房源。

| 项 | 说明 |
|---|---|
| 入口 | 列表页顶部筛选栏新增"排序"下拉，默认"最新上架" |
| 选项 | 最新上架（默认，按审核通过时间倒序）、价格从低到高、价格从高到低、面积从大到小、面积从小到大（面积选项依赖 F3 上线后展示） |
| 排序口径 | 价格按公寓 `min_monthly_rent`；面积按公寓所有房型最小面积；空值排最后 |
| 交互 | 切换排序后重置分页、回到顶部、保留已选筛选条件 |
| 异常 | 排序接口超时：保留当前列表数据，toast"排序加载失败，请重试" |

**验收（Given-When-Then）**
- Given 列表有 3 套房源（最低价 2000/3000/2500），When 选择"价格从低到高"，Then 顺序为 2000→2500→3000，且分页重置到第 1 页。
- Given 某房源无报价（"暂无报价"），When 按价格排序，Then 该房源排在最后。

### 4.2 F2 搜索扩展与搜索历史

**用户故事**：作为租客，我希望输入"中山公园"也能搜到附近房源，以便不记住公寓名也能找房。

| 项 | 说明 |
|---|---|
| 搜索范围 | 公寓名称 + 详细地址 + 描述，模糊匹配（权重：名称 > 地址 > 描述） |
| 搜索历史 | 仅本地存储（localStorage），最多 10 条，最新在前；支持单条删除与一键清空；未登录也可用 |
| 空结果 | 展示空态 + "试试搜索行政区或街道名"提示 + 热门区域快捷词（取房源数 Top5 行政区，【待确认】是否运营可配） |
| 边界 | 关键词长度 ≤ 30 字，超出截断；纯空格视为未输入 |

**验收**
- Given 存在描述含"近中山公园地铁站"的房源，When 搜索"中山公园"，Then 该房源出现在结果中。
- Given 已搜索过"徐汇""静安"，When 再次打开搜索弹窗，Then 历史区展示"静安、徐汇"（最新在前），点击"徐汇"直接执行搜索。

### 4.3 F3 房源字段扩展

**用户故事**：作为租客，我希望看到面积、朝向和除租金外的全部费用，以便不用打电话就能判断房源是否符合预期。

新增/变更字段（详见 §5 数据字典）：

| 字段 | 所属 | 必填 | 说明 |
|---|---|---|---|
| 面积 area | 房型 RoomType | 必填 | 数值，0.5–500 ㎡ |
| 朝向 orientation | 房型 RoomType | 必填 | 复用已有朝向字典（V1.0 字典已建未用） |
| 可入住时间 available_date | 房型 RoomType | 选填 | 日期，默认"随时入住" |
| 物业费 property_fee | 公寓 Apartment | 选填 | 元/月，0 表示免物业费 |
| 水费/电费 water_fee/electric_fee | 公寓 Apartment | 选填 | 枚举：民水民电/商水商电/按表计费【待确认枚举口径】 |
| 服务费 service_fee | 公寓 Apartment | 选填 | 元/月或比例，默认 0 |
| 网费/其他 other_fees | 公寓 Apartment | 选填 | 文本 ≤ 100 字 |

- 历史数据处理：存量房源上述字段为空，列表/详情正常降级展示（不显示对应行），不强制商家补录；商家下次编辑时提示补全【待确认：是否对存量房源发起补录运营动作】。
- 筛选联动：面积进入排序口径（F1）；费用不进筛选器（本期）。

**验收**
- Given 商家发布时未填面积，When 点击提交审核，Then 阻断并提示"请填写房型面积"。
- Given 房源物业费为 0，When 租客查看详情费用模块，Then 展示"免物业费"而非"0 元/月"。

### 4.4 F4 详情页费用与配套展示

- 详情页新增"费用明细"卡片：月租金（各租期方案）+ 物业费 + 水电口径 + 服务费 + 其他，逐项列出，空项不展示。
- 新增"配套设施"区：复用设施标签，按"基础设施/卫浴/厨房/公共"分组展示（分组规则进字典配置，【待确认】分组口径）。
- 电话交互：点击联系电话弹出"拨打/复制"动作面板（移动端 `tel:` 直拨）。

**验收**
- Given 房源填写了物业费 200、民水民电、服务费 0，When 打开详情页，Then 费用卡片展示 3 行：物业费 ¥200/月、民水民电、服务费 无。

### 4.5 F5 PC 端响应式

**用户故事**：作为商家/管理员，我希望在 PC 浏览器正常操作后台，以便高效发布与审核。

| 断点 | 布局 |
|---|---|
| < 768px | 现有 H5 布局不变 |
| 768–1280px | 列表双列卡片；详情页左右分栏（图左文右） |
| ≥ 1280px | 列表三列卡片；发布/审核表单最大宽 960px 居中；审核对比页双栏并排 |

- 移除 `App.vue` 写死的 `max-width: 480px`；底部 TabBar 在 ≥768px 时替换为顶部导航栏。
- 悬浮发布按钮改为右下角固定定位，去除硬编码坐标 `{x:320,y:500}`。
- 管理审核页 PC 端为优先优化对象（管理员主战场）。

**验收**
- Given 浏览器宽 1440px，When 打开房源列表，Then 卡片三列展示且无横向滚动条。
- Given 浏览器宽 375px，When 打开任意页面，Then 与 V1.0 移动端表现一致（回归）。

### 4.6 F6 登录态无感续期

- Axios 响应拦截遇 401 时，先静默调 refresh 接口换新 access token 并重放原请求；refresh 也失效才登出跳登录。
- 并发请求只触发一次 refresh（请求队列等待）。
- 不改变现有 token 有效期配置（access 30min / refresh 7d）。

**验收**
- Given access token 过期、refresh 有效，When 用户点击收藏，Then 请求成功且无跳转登录页。
- Given refresh 也过期，When 任意鉴权请求，Then 清除登录态并跳转登录页。

### 4.7 F7 站内信跳转

- 驳回类站内信：点击后标记已读并跳转对应房源编辑页（V1.0 PRD §7.3 已定义，本期补实现）。
- 消息列表项展示关联房源名称；房源已删除时跳转降级为 toast"该房源已删除"。

**验收**
- Given 商家收到首次驳回站内信，When 点击该消息，Then 标记已读并进入对应房源编辑页。

### 4.8 F8 存量缺陷清零

| 缺陷 | 修复口径 |
|---|---|
| 手机号号段校验失败用例 | 对齐测试用例的号段规则（1 开头 11 位 + 有效号段） |
| 详情页字典 label 未翻译 | 详情页渲染统一走字典 label 映射，禁止直接渲染 code |
| 收藏列表名称字段映射错误 | 对齐收藏接口返回结构与卡片字段 |
| 硬编码 | 列表页 16 区排序 Map、户型/租期字典改为后端 SystemDict 下发；悬浮按钮坐标改相对定位 |
| 调试遗留 | 删除 `server/_debug_pwd.py`、`server/config/test3`；预置管理员密码从文档/compose 明文改为环境变量注入【待确认：是否同步修改线上 admin 密码】 |

**验收**：`test/ui` 44 条用例 100% 通过；代码库 grep 无上述硬编码残留。

### 4.9 F9 地图找房（P1）

**用户故事**：作为租客，我希望在地图上看到房源分布并圈选区域，以便按通勤范围找房。

| 项 | 说明 |
|---|---|
| 入口 | 列表页顶部"地图"切换按钮，列表/地图双视图互切，筛选条件双向同步 |
| 数据 | 房源需经纬度：发布表单在选定行政区+街道+门牌后调用地理编码自动落点，允许商家在地图上微调【待确认：地图服务商选型，高德/腾讯，涉及 Key 与配额】 |
| 展示 | 缩放级别低时按街道聚合显示数量气泡；放大后展示单房源价格标记；点击标记弹出房源摘要卡（图/名/价），点击卡片进详情 |
| 边界 | 无经纬度的存量房源不出现在地图视图（列表视图不受影响）；地理编码失败允许商家手动打点 |

**验收**
- Given 筛选"徐汇区+3000 以下"，When 切换到地图视图，Then 地图仅展示符合条件的房源标记，且聚合数量与列表总数一致。

### 4.10 F10 详情页位置与周边（P1）

- 详情页新增"位置及周边"模块：静态地图缩略图（点击跳大地图）+ 周边 1km 内地铁/公交/商超文字列表（名称+距离）。
- 数据来源：地图服务商 POI 接口；无经纬度房源该模块整体隐藏。

**验收**
- Given 房源有经纬度，When 打开详情页，Then 位置模块展示地图缩略图与至少地铁/公交两类 POI 列表。

### 4.11 F11 信任体系（P1）

| 项 | 说明 |
|---|---|
| 平台核验标识 | 管理员审核通过时可选勾选"已实地/视频核验"，详情页与列表卡片展示"平台核验"徽章；默认不勾选 |
| 实拍提示 | 发布页图片上传区增加文案"请上传实拍图，过度美化或网图将被驳回"；审核驳回原因字典新增"图片非实拍" |
| 商家信息 | 详情页展示商家认证标识（已验证手机号）与在架房源数；不展示真实姓名等隐私信息 |

**验收**
- Given 管理员审核通过且勾选核验，When 租客查看列表，Then 对应卡片展示"平台核验"徽章。

### 4.12 F12 商家发布体验（P1）

- 发布表单同步新增 F3 字段（面积/朝向必填，费用选填）。
- 图片上传：前端压缩（长边 ≤ 2000px，≤ 5MB 限制不变）、拖拽排序、上传失败可单张重试。
- 草稿：表单内容本地自动保存（每 30s），意外退出后再次进入提示"恢复上次编辑"；提交成功后清除草稿。

**验收**
- Given 商家填写一半表单后刷新页面，When 再次进入发布页，Then 提示恢复草稿且已填字段还原。

### 4.13 F13 地铁筛选（P1）

- 筛选抽屉新增"地铁"维度：线路（1–18 号线等）→ 站点多选；与行政区筛选取并集逻辑【待确认：地铁与行政区叠加时是 AND 还是 OR】。
- 依赖：房源经纬度（F9）+ 站点 POI 库；按"距站点 ≤ 1.5km"判定归属【待确认距离口径】。
- 无经纬度房源不被地铁筛选命中。

### 4.14 F14–F18（P2，定义从简）

- **F14 浏览历史**：本地记录最近 50 条浏览过的房源，个人中心新增入口，支持清空；未登录可用。
- **F15 房源对比**：列表卡片长按/勾选进入对比模式，最多 3 套；对比页并排展示价格/面积/朝向/费用/设施差异。
- **F16 分享**：详情页新增分享按钮，生成带封面/名称/价格的分享图或复制链接；微信环境引导右上角分享。
- **F17 通知扩展**：审核通过发站内信（类型 audit_approved）；新增系统通知类型 system，支持后台手动群发【待确认：是否需要运营后台，或仅命令行】。
- **F18 商家数据**：商家"我的房源"卡片展示近 30 天浏览量/收藏数；统计口径：浏览量按详情页 PV（去重按用户+日），收藏数为当前有效收藏数。

## 6. 交互流程说明

### 6.1 找房主流程（变更后）

```
列表页(默认最新排序)
  ├─ 搜索弹窗：历史记录 → 输入关键词(名称/地址/描述) → 结果列表
  ├─ 筛选抽屉：行政区→街道 / 户型 / 租期 / 价格 / [地铁] → 应用 → 列表刷新(保留排序)
  ├─ 排序下拉：切换 → 重置分页 → 列表刷新
  ├─ [地图视图切换]：筛选同步 → 聚合气泡 → 房源标记 → 摘要卡 → 详情页
  └─ 卡片点击 → 详情页(费用明细/位置周边/平台核验) → 户型详情 → 电话拨打/收藏/分享
```

### 6.2 状态流转

- 房源状态机不变（draft → pending_first_review → published / first_rejected）。
- 新增：`verified` 标识独立于状态机，仅 published 房源可被勾选，取消勾选即时生效。

### 6.3 异常流与边界

| 场景 | 处理 |
|---|---|
| 地理编码失败 | 发布不阻断，提示"定位失败可在地图上手动打点"；无坐标房源不进地图/地铁筛选 |
| 地图服务配额耗尽/超时 | 地图视图降级为列表视图 + toast 提示；详情页位置模块隐藏 |
| 搜索接口超时 | 保留旧结果，toast 提示重试 |
| 筛选结果为空 | 空态 + "清除筛选"快捷按钮 |
| 并发：商家编辑中房源被管理员驳回 | 以后提交者覆盖，编辑页进入时校验房源版本，版本失效提示刷新 |
| 极限值 | 面积 0.5/500 边界、价格输入 0/负数拦截、搜索词 30 字截断、历史记录 10/50 条上限 |
