# 上海本地公寓出租平台 Web端 需求说明书（V1.0）

> 适用场景：前后端分离架构，移动端H5优先适配，兼容PC响应式；可直接输入架构师Agent完成拆解与Issue生成。

## 一、项目概述

1. **项目定位**：上海本地化公寓出租信息服务平台，连接公寓商家与租房用户，覆盖「房源发布 → 平台审核 → 租户检索 → 收藏管理 → 消息通知」完整业务闭环。
2. **终端形态**：Web单页应用，以375px宽度为H5适配基准，兼容主流手机屏幕；PC端访问自动响应式布局。
3. **架构模式**：前后端完全分离，后端提供RESTful API，前端独立部署；接口统一返回体、统一错误码规范。
4. **本期范围**：V1.0实现核心房源全流程、三级用户体系、审核机制、站内信与短信通知，不含在线签约、支付、IM聊天功能。

## 二、用户角色与权限


| 角色    | 核心权限                              |
| ----- | --------------------------------- |
| 租客用户  | 浏览房源、组合筛选、收藏房源、查看详情、个人中心基础管理      |
| 商家用户  | 发布公寓、编辑房源、提交审核、管理自有房源、查看审核结果、接收通知 |
| 平台管理员 | 审核首次提交房源、审核房源变更申请、执行通过/驳回操作       |


**预置管理员账号**：系统初始化自动生成，账号 `admin123`，密码 `3816832z`，拥有管理员全部权限。

## 三、账号体系与认证模块

### 3.1 用户注册

- 唯一注册方式：手机号 + 短信验证码
- 流程：输入手机号 → 获取并填写验证码 → 设置登录密码 → 注册成功
- 校验规则：手机号格式校验、验证码5分钟有效期、同手机号1分钟限发1次、1小时限发10次
- 密码规则：支持6-20位字符，加密存储，禁止明文落库

### 3.2 用户登录

- 支持两种登录方式：手机号+密码登录、手机号+短信验证码登录
- **首次登录强制身份选择**：登录成功后必须选择「我要租房」或「我要出租」，选定后方可进入房源列表页；身份标识用于控制页面权限与功能入口。

### 3.3 忘记密码

- 仅支持「手机号+短信验证码」重置，不支持邮箱找回
- 流程：输入手机号 → 验证验证码 → 设置新密码 → 重置成功

### 3.4 修改密码（个人中心内）

- 登录状态下必须通过短信验证码验证身份，方可设置新密码
- 不支持仅输入原密码直接修改

### 3.5 接口鉴权规则

- 公开接口（无需登录）：房源列表、房源详情、户型详情、注册、登录、忘记密码、获取短信验证码
- 需鉴权接口：收藏、消息、房源发布/编辑/删除、个人中心管理、审核功能
- 权限隔离：商家、管理员专属接口，非对应角色访问返回403权限错误

## 四、房源发布模块（商家端专属）

### 4.1 发布入口

- 商家身份登录后，房源列表页右下角显示悬浮「+」发布按钮
- 租客身份登录时，页面不展示该按钮

### 4.2 公寓基础信息（全部必填）

- 公寓总览图：1张主图，支持上传预览、删除重传
- 公寓名称：文本输入，长度限制2-50字
- 公寓描述：多行文本输入，长度限制500字内
- 所在位置：两级联动选择「上海行政区 → 街道/镇」，支持补充详细门牌号
- 联系电话：商家联系手机号，格式校验

### 4.3 房型信息管理（多组弹窗式）

- 一个公寓可添加多组房型，**至少添加1组方可提交审核**
- 操作交互：点击按钮弹出房型编辑弹窗 → 填写保存后关闭弹窗 → 主页面展示已保存房型名称列表 → 点击名称可再次弹窗编辑
- 单房型必填字段：
   1. 房型图片：最多上传5张，支持排序、预览、删除
   2. 房型名称：文本输入（如「朝南主卧」「一室一厅整租」）
   3. 房屋设施：多选标签（预置：空调、洗衣机、冰箱、宽带、热水器、衣柜、独立卫浴、阳台、厨房）
   4. 户型：下拉选择（一室、两室一厅、两室两厅、三室一厅、三室两厅）
   5. 内外窗：下拉选择（内窗、外窗）
   6. 窗户朝向：下拉选择（东、南、西、北、东南、西南、东北、西北）
   7. 楼层：数字输入
   8. **租期租金方案（支持多组）**：每组包含三个固定字段
      - 租期：下拉选项（1个月、半年、1年、18个月、2年）
      - 月租金：数字输入，单位：元
      - 支付方式：下拉二选一（押一付一、押一付三）

### 4.4 提交审核

- 页面底部设置「提交审核」按钮，所有字段校验通过且至少1组房型后方可点击
- 提交后房源状态变为「审核中-首次提交」，审核期间商家不可编辑房源
- 审核通过：状态变为「已上架」，进入公共房源列表对外展示
- 审核驳回：状态变为「审核失败」，触发驳回通知，商家可编辑后重新提交

## 五、房源列表与筛选模块

### 5.1 列表展示规则

- 默认排序：按房源上架时间（审核通过时间）倒序排列
- 单卡片展示内容：公寓总览图、公寓名称、所在位置、该公寓所有房型中的**最低月租金**
- 可见范围：
   - 租客：仅可见「已上架」状态的房源
   - 商家：公共列表仅展示已上架房源，自有房源在「已上架房源」菜单查看全状态

### 5.2 组合筛选功能（支持多条件叠加）

1. 名称模糊搜索：输入公寓名称关键词检索
2. 行政区筛选：上海16个行政区下拉选择
3. 街道/镇筛选：与行政区联动，选中行政区后加载对应辖区内街道/镇选项
4. 户型筛选：下拉选择户型类型
5. 租期筛选：下拉选择租期时长
6. 价格筛选：月租金区间（最低价、最高价）

> 行政区划数据采用上海市民政局发布的最新官方区划：全市16个市辖区，对应108个街道、106个镇、2个乡，作为系统预置字典。

## 六、房源详情与户型详情模块

### 6.1 公寓房源详情页

- **入口**：房源列表卡片点击进入、个人中心收藏列表点击进入
- 页面形态：与发布页结构一致，所有字段只读不可编辑
- 页面内容：
   1. 公寓总览图展示
   2. 公寓名称、所在位置、联系电话
   3. 公寓详细描述
   4. 收藏按钮：支持收藏/取消收藏，已收藏状态高亮
   5. 房型卡片列表：展示该公寓下所有房型，单卡片展示：房型首张图、房型名称、最低月租金、户型、楼层

### 6.2 户型详情页

- **入口**：点击房源详情页的房型卡片进入
- 页面展示该房型全部信息：图片轮播、房型名称、房屋设施标签、户型、内外窗、朝向、楼层、全部租期租金方案列表
- 提供返回按钮，回到对应公寓房源详情页

## 七、个人中心模块

### 7.1 个人中心首页

- 顶部展示当前登录用户手机号
- 功能菜单按角色差异化展示：
   - 租客：收藏、消息、修改密码
   - 商家：收藏、消息、修改密码、已上架房源
   - 管理员：收藏、消息、修改密码、审核

### 7.2 我的收藏

- 按收藏时间倒序展示收藏的公寓房源列表
- 卡片展示内容与公共房源列表一致
- 点击卡片跳转房源详情页，支持取消收藏

### 7.3 我的消息（站内信）

- 按时间倒序展示站内信列表
- 主要消息类型：房源审核通过通知、房源审核驳回通知
- 区分已读/未读状态，点击消息标记为已读
- 审核驳回类消息，点击后直接跳转至对应房源编辑页

### 7.4 修改密码

- 跳转独立修改密码页
- 必须验证短信验证码后方可设置新密码

### 7.5 已上架房源（商家专属）

- 两个Tab页：**已上架**、**审核中**
- 审核中Tab区分两类单据：首次提交审核、变更审核
- 排序：均按对应时间倒序排列
- **删除规则**：
   - 删除「首次提交审核」单据：对应房源数据执行逻辑删除
   - 删除「变更审核」单据：房源原信息不变，仅变更请求逻辑删除
- 支持单条删除、批量选择删除：删除房源时自动下架，同步删除关联的提交/变更审核单
- 点击房源卡片跳转至「房源详情编辑页」

### 7.6 房源详情编辑页

- 商家可编辑房源全部内容，字段规则与发布页一致
- **提交生效规则**：
   - 未修改「公寓名称」「所在位置」字段：提交后直接更新房源信息，即时生效
   - 修改了「公寓名称」或「所在位置」字段：提交后生成「变更审核单」，状态为变更审核中；审核期间原房源信息保持不变，审核通过后变更内容正式生效
- 房型信息支持新增、编辑、删除，规则同发布页

## 八、管理员审核模块

### 8.1 审核入口与总览

- 管理员个人中心展示「审核」菜单，点击进入审核列表页
- 列表分为两个Tab：**提交审核**、**变更审核**

### 8.2 Tab1：提交审核（首次提交）

- 展示所有「首次提交审核中」的房源卡片，按提交时间倒序排列
- 点击卡片进入审核详情页，展示公寓全部信息（基础信息+所有房型），展示形态同公寓详情页
- 页面底部操作区：
   - 驳回原因输入框：填写审核失败具体原因
   - 通过按钮：点击后房源状态变为「已上架」，正式对外展示
   - 拒绝按钮：点击后房源状态变为「审核失败」，触发驳回通知

### 8.3 Tab2：变更审核

- 展示所有「变更审核中」的申请卡片，按提交时间倒序排列
- 点击卡片进入审核详情页，展示公寓最新信息，**发生变更的字段以红色高亮标注**
- 页面底部操作区：
   - 驳回原因输入框：填写审核失败具体原因
   - 通过按钮：点击后变更内容正式生效，更新房源展示信息
   - 拒绝按钮：点击后变更申请作废，房源原信息保持不变，触发驳回通知

## 九、通知机制

### 9.1 触发场景

房源审核驳回（首次提交驳回、变更申请驳回）

### 9.2 双渠道通知

1. **短信通知**：通过阿里云短信向商家绑定手机号发送审核驳回短信，包含驳回原因简要提示
2. **站内信通知**：向商家消息中心发送站内信，包含房源信息、驳回原因、跳转编辑页入口

### 9.3 审核通过场景

仅更新房源状态，不发送主动通知。

## 十、第三方服务预留

### 10.1 阿里云短信服务

- 所有短信发送对接阿里云短信
- 配置项全部预留：AccessKey ID、AccessKey Secret、短信签名、短信模板CODE
- 支持通过环境变量注入，禁止硬编码到代码中

### 10.2 图片存储服务

- 图片上传接口预留存储适配层
- 本期默认本地存储，预留阿里云OSS配置项，支持无缝切换

## 十一、预置数据

1. **行政区划字典**：上海市16个行政区及对应街道/镇两级联动数据，基于官方区划初始化
2. **系统字典**：户型、房屋设施、租期、支付方式、朝向、内外窗等下拉选项固定值
3. **管理员账号**：系统启动初始化 `admin123 / 3816832z` 超级管理员账号
4. 所有删除操作均采用**逻辑删除**，保留数据痕迹与操作记录

## 十二、非功能需求

1. **移动端适配**：H5优先，兼容iOS/Android主流机型浏览器，无样式错乱、按钮不可点问题
2. **性能要求**：列表分页加载，图片懒加载与压缩，首屏加载控制在合理范围
3. **安全要求**：密码加密存储、验证码频控、接口参数校验、防越权访问
4. **可扩展性**：用户身份、房源状态、审核类型预留扩展位，后续迭代无需重构核心表结构
